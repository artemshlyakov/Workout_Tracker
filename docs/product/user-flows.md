# Critical user flows — v0.5

## A. Первая регистрация (с интернетом)
Владелец при **временно включённом signup** открывает приложение онлайн → вводит **реальный** email и пароль → Supabase создаёт аккаунт и сразу выдаёт session без email confirmation → появляется пустой приватный журнал. Администратор **выключает signup в Supabase**. Посторонние посетители видят только вход и `Регистрация временно закрыта`; созданные аккаунты изолированы RLS.

## B. Обычный вход (с интернетом)
Email-пароль проверяется Supabase; восстановление через email/подтверждение адреса в закрытом пилоте **не работают** и не должны выглядеть работающими.
Supabase Auth подтверждает пользователя → приложение выбирает локальную область по **user ID** → отображает только личную историю → при подключении получает изменения из Supabase. Логин/пароль не сохраняются в собственных таблицах.

## C. Офлайн-тренировка после предыдущего входа
Пользователь, который уже входил и не выходил на этом устройстве, открывает установленную PWA в режиме полёта → shell загружается из кеша → видит **свою** историю из IndexedDB → добавляет 80 кг × 10 повторений → атомарный local commit record+outbox → `На устройстве · ожидает синхронизации` → при восстановлении связи и проверке identity отправка в Supabase → после ack `Синхронизировано`.

## D. Офлайн-первый вход
Человек впервые открывает установленный PWA и ещё не авторизован, либо ранее явно вышел → экран входа сообщает `Для входа требуется интернет`; без аккаунта нельзя открыть личные тренировки и создать новый пользовательский журнал.

## E. Быстрое добавление подходов
Выбрать упражнение, записать вес и повторы, следующий подход создаётся с предыдущим весом; правка/удаление оставляет корректный outbox и синхронизируется позже. При ошибке IndexedDB показать `Не удалось сохранить`.

## F. Прогресс / история
Просмотр ранее созданных тренировок и предыдущих результатов своего user ID; на втором устройстве данные становятся доступны после успешной облачной синхронизации.

## G. Смена аккаунта и выход
С pending изменениями спросить подтверждение: синхронизировать сейчас либо экспортировать локальную копию. После явного выхода скрыть и закрыть пользовательский кеш (даже офлайн), не переносить его в следующий аккаунт. При повторном входе той же identity возможно корректное восстановление по согласованной политике.

## H. Одновременное изменение
На устройствах A и B пользователь изменяет один подход → server revision mismatch → обе версии сохраняются для выбора; запрещён silent last-write-wins.

## I. Резервная копия
Пользователь экспортирует JSON; восстановление валидирует формат, владельца, конфликты и подтверждение. В Plan 002 есть только импорт тестовой dev-области с полной заменой после подтверждения; импорт между реальными аккаунтами остаётся отложенным. Не загружать резервную копию одного пользователя в другой без явной безопасной процедуры импорта, которую потребуется отдельно утвердить.

## Plan 001 demo only
React state, seed workout, баннер `Демо — данные не сохраняются`; reload сбрасывает состояние; реальная авторизация и облачная отправка отсутствуют. Допустим только в dev/test.

## Plan 006: ежедневный сценарий

Актуальная последовательность начала, выбора нескольких упражнений, сохранения строк, завершения/исправления, календаря, экспорта/восстановления и iPhone PWA описана в `../operations/personal-diary.md`. Черновики сохраняются только на устройстве; импорт добавляет копии, не заменяет журнал.

## Plan 008: заранее составленная тренировка

Пользователь создаёт сохранённую тренировку с произвольным названием и выбирает несколько упражнений из библиотеки или вводит свои, меняет их порядок и сохраняет без подходов. Позже нажимает «Начать» у этой тренировки, заносит веса и повторы в созданную запись и завершает её. Календарь показывает название записи в выбранный день. Редактирование или удаление сохранённого состава не изменяет уже проведённые тренировки. Образец «Грудь и бицепс» не создаётся автоматически.

## Plan 009: графики и мобильный выбор

После первой завершённой тренировки с подходами раздел «Прогресс» показывает точку реального дневного объёма. За разные даты точки соединяются линией. По выбранному упражнению отображается лучший рабочий вес за день; поиск и выбор выполняются в нижней панели. Если нет завершённых записей, графики не рисуются. Фильтры библиотеки упражнений открываются в таких же аккуратных панелях; иллюстрации миниатюр кадрируются без пустых светлых полей.
