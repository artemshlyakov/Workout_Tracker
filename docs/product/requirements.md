# Product requirements — Workout Tracker v0.5

**Status: accepted auth-required + offline-first for a closed personal pilot (2026-10-20).** Mobile-first in gym, Russian UI, weights kg, free-only technology.

## Primary user story
Первый владелец регистрируется при временно разрешённом signup; затем регистрация новых пользователей закрывается сервером. Каждый созданный аккаунт изолирован, но **открытая регистрация для всех не входит в текущий пилот**. После первого входа на устройстве он сможет записывать подходы без интернета, затем синхронизировать их в свой аккаунт.

## Required before first real use / Plan 004 gate
1. Экран входа и разовая регистрация email+пароль без проверки адреса для закрытого пилота. После первого аккаунта отключить signup. Восстановление через email пока недоступно; не имитировать его. Открытые регистрации — отдельный gate.
2. Если пользователь не вошёл — личный журнал и история не отображаются. Для каждого пользователя собственный профиль и данные.
3. RLS + grants в Supabase изолируют User A, User B и anon на уровне всей БД, включая вложенные ссылки, и протестированы.
4. После ранее успешного входа: офлайн-первичная локальная запись, атомарный IndexedDB commit (record + outbox), ожидание синхронизации; до первого входа требуется сеть.
5. Добавить/переименовать/закончить/исправить тренировку; свой каталог упражнений, подходы, порядок; история; предыдущие веса.
6. Вес до 2 знаков (запятая/точка), повторения целые, проверка данных; безопасное удаление/undo.
7. Раздельные статусы `На устройстве`, `Ожидает синхронизации`, `Синхронизировано`, `Ошибка`, `Конфликт` и статус авторизации.
8. Защита от повторной записи, server-owned revision, conflicts, пользователь не теряет записи после разрыва сети/перезапуска.
9. Версионируемые JSON экспорт и импорт, тест восстановления, без автоматического смешивания аккаунтов.
10. Удобно с телефона одной рукой, 360px+, доступные кнопки >=44px, никаких горизонтальных переполнений.

## Deferred
Публичные ленты тренировок, социальные профили, Google/другие провайдеры как второй способ (если email/password работает), платные функции, AI, носимые устройства, фото упражнений, автоматический фоновый sync при закрытом приложении.

## Slice boundaries
- 001: интерфейс демо, **без аккаунта и сохранения**; не публиковать для использования.
- 002: IndexedDB/PWA в dev test-only local profile, не объявлять продукт публичным.
- 003: Auth/RLS без email verification в закрытом личном пилоте, user-scoped cache, basic sync, отключение signup после аккаунта владельца.
- 004: надёжность, A/B/anon тесты, offline device tests — gate закрытого личного пилота.
