# ADR 0008: черновики, повторный pull и восстановление личного дневника

Принято 2026-10-23 в рамках Plan 006 по поручению владельца довести и опубликовать личный дневник.

- Сохраняем React/TypeScript + Dexie + Supabase RPC. SQL, RLS, схема облака и версия Dexie не меняются.
- В неиндексируемые metadata workspace добавляем черновик активной тренировки (включая отдельный флаг изменения названия и deadline отдыха). Черновик привязан к owner/workout, не считается выполненным подходом и не создаёт outbox. Валидная явная запись по-прежнему атомарна с outbox.
- При отсутствии очереди/грязного черновика pull читает все четыре таблицы страницами по 500, с сортировкой по UUID, и применяет только более новые serverRevision. Повторная проверка очереди/черновика внутри транзакции защищает ввод во время сети. Отсутствие строки в ответе не означает удаления; нужны tombstones. Неполный граф ссылок отклоняется. Это не серверный MVCC snapshot, следующий pull исправляет отставание конкурентных чтений.
- Push сериализуется Web Locks по owner там, где API доступен; RPC ledger/CAS остаются обязательной защитой. Retry ограничен пятью попытками с экспоненциальной задержкой/jitter, запросы ограничены 20 секундами. Unknown ack повторяет прежний UUID и base revision.
- Конфликт показывается как две версии. Перед выбором заново читается облачная revision, внутри транзакции проверяются текущие operation/localRevision. Выбор local создаёт новую операцию на проверенной revision; cloud удаляет только очередь этой сущности. Удалённые родители с pending-потомками требуют отдельного восстановления из экспорта; silent discard запрещён.
- Импорт проверяет владельца/формат/ссылки/числа, добавляет новые UUID и новые операции атомарно. Старые outbox из файла не воспроизводятся. Это копирование, не merge. Повторный SHA-256 файла блокируется в metadata устройства; другой файл/устройство может создать ещё копии.
- Каталог справочный и публичный; выбранные упражнения попадают в существующую таблицу exercises. Инструкции и картинки не меняют пользовательскую схему. Нет новых внешних платных сервисов.
- Service Worker кеширует только shell/публичные иллюстрации. API, JWT и личные данные не попадают в CacheStorage. Обновление активирует пользователь вне открытой тренировки.

Ограничения: нет гарантированных фоновых iOS-уведомлений, автоматического слияния двух активных тренировок, duration/distance-подходов. Полный реальный браузерный Auth/offline/online gate остаётся открытым; локальные проверки описываются отдельно.
