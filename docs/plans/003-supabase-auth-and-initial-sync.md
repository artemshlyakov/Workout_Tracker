# Plan 003 — Supabase email/password (closed personal pilot), RLS + initial sync

**Status:** PLANNED after Plan 002. Дизайн принят, техническое решение о пилотной авторизации — ADR 0007. Создание Supabase проекта и изменение настроек выполняет владелец или подтверждает отдельно.

## Прочитать
`AGENTS.md`, `ARCHITECTURE.md`, `docs/architecture/{auth,security,data-model,offline-sync}.md`, ADR 0006 и ADR 0007, `docs/quality/acceptance.md`.

## До реализации
1. Создать Supabase Free проект. Включить email/password; на время **закрытого личного пилота** выставить `Confirm Email = OFF` (email по факту не проверяется). Первую регистрацию провести с реальным, доступным email.
2. После регистрации владельца выставить `Allow new users to sign up = OFF`; проверить, что существующий пользователь продолжает входить, а новый signup отклоняется **сервером**. Для тестирования A/B временно разрешать регистрацию и потом снова отключать.
3. Не настраивать SMTP и email reset в этом плане. Показать честное сообщение, что восстановление пароля пока недоступно. Не показывать фиктивный flow восстановления или подтверждения.
4. Не запускать `supabase/drafts/legacy_cloud_only_v0_2_NOT_FOR_EXECUTION.sql`. Подготовить проверенную миграцию: owner-aware FKs, RLS/grants, revisions, op ledger, RPC/CAS. Пользователь согласует SQL и миграции перед реальным применением.

## Работы
- Авторизация через Supabase Auth: signup (пока сервер разрешает), login, logout, auth gate, понятные ошибки, profile email. Отдельный клиентский UI-флаг открытия регистрации — только для интерфейса, не для безопасности.
- Workspace, история и outbox по стабильному `auth.uid()`, без автоматической миграции test-only data из Plan 002.
- Предварительный sync с постоянными UUID и operation IDs; отправка только из account-scoped outbox. Истекшая/неподтверждённая онлайн-сессия блокирует sync, сохраняя локальные данные.
- Негативные тесты REST/RPC/SQL для A, B, anon (включая подставленные FK). Браузер содержит только URL и publishable key.
- Проверка sign-in и session restore на настоящем Pages URL; с email/password подтверждающих callback-URL нет, их не имитировать.

## DoD
A входит, видит только свои записи, выходит и снова входит. После закрытия регистрации новый пользователь создать аккаунт не может, существующий A продолжает входить. User B (отдельный тестовый аккаунт) и anon не читают и не изменяют A ни через UI, ни через прямые API-вызовы. Sync не отправляет A от имени B. Все реальные проверки отражены в отчёте, без заявлений о непроведённых тестах. Подтверждения email и email-reset пока **не обещаются**.

## Вне границ
SMTP, public signup, подтверждение email, Google OAuth, полноценное разрешение конкурентных конфликтов, графики.
