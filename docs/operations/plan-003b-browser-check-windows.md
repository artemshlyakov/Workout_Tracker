# Plan 003B: браузерная проверка на Windows

Выполнять в обычном Chrome или Edge с доступом к Supabase по штатному HTTPS. Использовать два контролируемых аккаунта, пароли от которых известны только владельцу. Пароли случайных A/B, созданных агентом для API-тестов, хранились только в его временной среде и не передаются через GitHub. Если своих двух аккаунтов нет, создавать их только в короткое согласованное окно регистрации по `docs/operations/supabase-private-pilot.md`, после чего сразу выключить `Allow new users to sign up` и проверить это в новом сеансе. Не открывать массовую регистрацию.

1. В PowerShell: `git fetch origin`, `git switch feat/plan-003b-auth-sync`, `git pull --ff-only`, `npm ci`, `npm run build`, `npm run preview`. Открыть адрес, который напечатает Vite (обычно `http://localhost:4173/Workout_Tracker/`). Draft PR #5 ещё не опубликован на Pages: текущий Pages URL показывает `main`.
2. Открыть DevTools → Console и Network. Войти как A. Убедиться, что появилась пустая личная тренировка, затем статус «Облако подтвердило все изменения». Переименовать тренировку, добавить подход, изменить вес и повторы, удалить другой подход. После каждой операции дождаться облачного подтверждения. Обновить страницу: данные и статус должны восстановиться. Сделать «Экспорт», проверить, что скачан JSON только текущего аккаунта; не отправлять его в PR или чат.
3. После успешного входа A в DevTools → Network выбрать **Offline**. Добавить и изменить подход, обновить страницу. Локальные записи должны остаться; статус должен сообщать об ожидании отправки. Вернуть **Online**, дождаться облачного подтверждения и обновить страницу ещё раз. Для проверки чистого профиля открыть отдельное окно InPrivate/Incognito, войти как A и проверить загрузку этих записей из облака.
4. В основном окне выйти из A и войти как B. Название и подходы A не должны появиться. Создать собственный подход B, дождаться подтверждения, выйти и вернуться к A: его журнал должен сохраниться, а данные B не должны появиться.
5. Для проверки выхода во время синхронизации включить в Network замедление (например, Slow 3G), сделать изменение и сразу нажать «Выйти». Если появится предупреждение об ожидающих изменениях, проверить его текст и выйти. Войти как B: очередь A не должна отображаться или отправляться от имени B. Вернуться к A, восстановить обычную сеть и проверить доставку его очереди.
6. На ширинах 360 и 390 px проверить отсутствие горизонтальной прокрутки и ошибок Console. При любой ошибке сохранить только код ошибки, шаг воспроизведения и статус из интерфейса; не копировать пароль, токены, содержимое JSON-экспорта или персональные записи.

Результат записать по каждому шагу как «прошёл/не прошёл» с браузером и датой. До успешных проверок не переводить Draft PR #5 в готовый к объединению.
